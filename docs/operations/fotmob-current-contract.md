# FotMob: календарь и детали в current (#1288)

Календарь определяет состав текущих матчей. Карточка входит в
`fotmob_match_payloads_current`, только если её точный ключ
`competition_id, source_season_key, match_id` присутствует в
`fotmob_matches_current`. ID пачек календаря и карточек независимы.
Физические данные карточек остаются в Bronze после исчезновения матча из
корректного непустого календаря.

## Входной контракт

Отсутствующий или неправильно типизированный список матчей не является пустым
календарём. Сохраняются поддерживаемые формы fixtures, matches, overview и
исторические ответы с реальными матчами только в сетке playoff.

Явный пустой список допустим для сезона без ранее опубликованных матчей.
Если этот точный сезон уже содержал успешно опубликованные матчи, операция
возвращает `schema_drift` без успешной публикации и без completion сезона.
Проверка действует при обычной загрузке, использовании prefetched-ответа,
replay и 304. История проверяется по физическим строкам с успешным манифестом
v1/v2, включая буфер до flush. Отказ чтения хранилища не разрешает публикацию
пустого снимка. Непустые календари не требуют дополнительного запроса истории.

## Существующие пустые пачки

Исправление входа не меняет уже сохранённые манифесты. При выборе календаря
current пустая успешная пачка не вытесняет предыдущий непустой снимок.
Явный `not_available` остаётся удалением; fallback через него не допускается.
Приоритет версии v2 над v1 и существующие правила ранжирования сохраняются.
Имена и колонки view, `fotmob-native-v2` и ID корректных пачек не меняются.

Контрольная пара raw 10618/2026 сохранена в `tests/fixtures/fotmob/` вместе
с provenance: хороший ответ содержит 30 матчей; более поздний ответ содержит
`fixtures.hasOngoingMatch` без списка. Source SHA проверен на исходных bytes
при чтении; файлы fixtures отдельно нормализованы и имеют собственные SHA.

## Проверка качества и оставшаяся приёмка

`scripts/fotmob_acceptance.py verify` добавляет глобальную проверку
`current_match_consistency`. Она охватывает все current, независимо от списка
сезонов конкретного запуска. В JSON `summary` печатаются:

- `payload_orphans`: карточки без соответствующего матча; ненулевое число
  проваливает проверку.
- `finished_without_payload`: завершённые матчи без карточки; диагностическое
  число, исторический добор выполняется отдельной задачей.
- `current_consistency_scope: "all_current"`.

При ошибке запроса счётчики равны `null`, проверка не пройдена. Ошибка не
превращается в фиктивный ноль. Включение новой проверки не создаёт расписаний
или уведомлений и не меняет сборщик #1185.

Разовая уборка старых фантомных сезонов описана в
[плане миграции](fotmob-1288-repair.md). Она не выполняется автоматически.

После отдельно разрешённой доставки и миграции нужно подтвердить:
10618/2026 содержит 30 матчей в current, глобальный `payload_orphans = 0`,
доказанные фантомные метки отсутствуют. Исходные числа 38 сирот и 49 фантомных
меток — исторические наблюдения, а не неизменяемые ожидаемые значения.
До этой проверки #1288 остаётся открытой. PR использует `Refs #1288`.

production-прогоны. Доставка #1287, её pin, campaign hold и STOP сохраняются.
