# Какие поля страницы матча FBref попадают в Bronze

Парсер читает сохранённую страницу матча. Для всех строк типизированных таблиц он записывает `match_id` исходной страницы, `source_competition_id` турнира и `source_season_id` сезона. Строка `typed:__complete__` в манифесте появляется после записи и проверки наборов этой версии страницы.

## Карточка матча

В `bronze.fbref_match_meta` одна строка на матч. В именах полей `home_` означает хозяев, `away_` — гостей. Блоки `sb_team_0` и `sb_team_1` явно задают стороны. В старой разметке FBref первым публикует блок хозяев, вторым — гостей. Чтобы использовать порядок, парсеру нужны ровно два блока команд.

| Колонки | Что записываем |
| --- | --- |
| `home_team`, `away_team`, `home_team_id`, `away_team_id` | Видимое название команды и идентификатор из ссылки FBref на её страницу. |
| `home_goals`, `away_goals` | Целочисленный счёт из основного элемента `.score` каждой команды. 0:0 сохраняется как два нуля. Серия пенальти в отдельном поле источника не прибавляется к этому счёту. |
| `home_xg`, `away_xg` | Опубликованные ожидаемые голы каждой команды из её элемента `.score_xg`. |
| `home_captain`, `away_captain`, `home_captain_id`, `away_captain_id` | Поле Captain в блоке команды задаёт имя и, при наличии ссылки, идентификатор игрока. Для общего поля Captain нужна ссылка на игрока. Сторону подтверждает состав, таблица игроков с идентификатором команды или ссылка на команду в самом поле. При противоречии или нескольких кандидатах у одной стороны значение остаётся пустым. |
| `venue`, `attendance` | Текст поля Venue и целое число зрителей из поля Attendance в блоке матча. Название и город сохраняются в том виде, в котором FBref указывает место проведения. |

Для превью команды и место уже могут быть известны. Отсутствующие значения сохраняются как SQL `NULL`. Такая запись не подтверждает готовность сыгранного матча. Если у страницы отсутствует блок матча, манифест отражает отсутствие источника. Если парсер видит два числовых результата и не может сопоставить их сторонам, запись этой версии завершается ошибкой.

## Составы и остальные наборы

| Набор | Что записываем |
| --- | --- |
| `fbref_lineups` | Команда, имя игрока, его идентификатор FBref, номер, признак стартового состава и позиция. `formation` сохраняет расстановку из заголовка таблицы своей команды, в том числе на строках скамейки. При отсутствии расстановки записывается `NULL`. |
| `fbref_match_events` | Показанные FBref тип и минута события, команда, сторона и участники со ссылками на игроков. |
| `fbref_match_team_stats` | Доступные показатели обеих команд из блока командной статистики, включая владение, удары, сейвы и карточки. |
| `fbref_match_player_stats`, `fbref_match_keeper_stats` | Доступные столбцы опубликованных таблиц игроков и вратарей обеих команд, игрок, команда и сторона. |
| `fbref_match_managers`, `fbref_match_officials` | Имена тренеров по сторонам и их идентификаторы из ссылок при наличии. Судейская бригада сохраняется по опубликованным ролям. |
| `fbref_shot_events` | Доступные строки таблицы ударов. Для матча без опубликованной таблицы доступность отражается в манифесте. |

Исходные HTML, общий реестр таблиц и их ячейки сохраняются отдельно. Примеры входных страниц и проверки опубликованных полей есть в [наборе матчей](../../tests/fixtures/fbref/matches/) и [тестах записи в Bronze](../../tests/unit/scrapers/test_fbref_match_metadata.py).

## Когда перепроверять отсутствующие данные

В `fbref_dataset_availability` поле `source_observed_at` хранит время исходной загрузки в UTC. Для пустого набора матча `review_after` наступает через 7 дней. Для отсутствующих ударов или набора со статусом `restricted` срок составляет 30 дней. Повторный разбор сохранённой страницы сохраняет исходный срок. При неизвестном времени загрузки обе даты остаются пустыми. Суточный отчёт отдельно показывает дату следующей проверки для шести исключённых сезонных маршрутов. Их последние документированные результаты относятся к [аудиту источника от 14 июля 2026 года](../reviews/fbref/2026-07-14-issue-945-production-readiness.md).

26 ноября 2026 года на 10 сохранённых страницах английской Премьер-лиги и 10 страницах японской J2 был контейнер `all_shots`. Ни на одной из 20 страниц таблица отдельных ударов не была опубликована, включая HTML-комментарии. Sports Reference сообщил об удалении расширенных данных прежнего поставщика из FBref и Stathead 20 января 2026 года. Сравнение одной страницы с входом и без входа для #1330 остаётся открытым. [Сообщение издателя](https://www.sports-reference.com/blog/2026/01/fbref-stathead-data-update/)

В общем реестре таблиц исходные блоки составов хозяев, гостей и общей статистики получают устойчивые имена `lineup_a`, `lineup_b` и `team_stats`. Изменение расстановки или перенос таблицы в HTML-комментарий сохраняет логическое имя. Физический идентификатор учитывает снимок, расположение и порядковый номер. Повторённые таблицы остаются отдельными записями.

Порог пустых составов проверяется на 14-й день после доставки по сохранённому списку сыгранных матчей. [Расчёт и условия приёмки #1330](fbref-lineups-day14.md)
