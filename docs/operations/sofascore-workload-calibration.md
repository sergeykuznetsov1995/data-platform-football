# Офлайн пересчёт статических бюджетов SofaScore (#1365)

Политика `configs/sofascore/workload_policy.json` остаётся статической v4.
Пересчёт не запускает запросы SofaScore и не меняет дневные потолки шлюзов,
размер пула, окружение или production. Обычный сбор продолжает использовать
подписанные аллокации и общий учёт фактических байтов.

## Правило пересчёта

`scripts/research/calibrate_sofascore_workload_policy.py` читает сохранённые
`sofascore_allocations.json` трёх шлюзов. В выборку входят только штатные DAG
`dag_ingest_sofascore`, `dag_backfill_sofascore_all_mens` и
`dag_refresh_sofascore_all_mens`. Способ запуска DAG не меняет правило:
платные canary и другие DAG исключены.

Окно — 30 суток перед заданным `--as-of`. Создание и последнее обновление run
должны целиком лежать в окне. Это консервативное условие исключает старые
долгие run, для которых нельзя точно восстановить время каждой аллокации.
Повторная копия той же аллокации не добавляет наблюдение; конфликтующие копии
останавливают пересчёт.

`hard_task_bytes` — максимум `spent_provider_bytes` успешных полных аллокаций.
Полный пакет содержит 25 матчей, 50 игроков или один сезон. Байты повторных
попыток входят в расход той же аллокации. Нулевой расход и незавершённые
аллокации не входят в максимум. При числе полных наблюдений меньше 30 старое
значение является нижней границей: его можно повысить, но нельзя снизить.

После этого внутри каждого формата сезона бюджеты проходят по team bands
`1_7 → 8_15 → 16_20 → 21_32 → 33_48 → 49_64 → 65_plus`.
Каждый следующий бюджет не меньше предыдущего. Это минимальные повышения,
необходимые для неубывающей последовательности; форматы не смешиваются.

`request_bound_bytes` хранит отдельно максимумы отдельных запросов по endpoint.
Сумма request map должна совпадать с расходом попытки, meter должен быть
`proxy_filter_provider_path_v2`. Измерения включают байты подготовки браузера,
которые шлюз относит к первому запросу. Данные завершённых аллокаций, включая
частичные пакеты и предыдущие попытки, могут повысить максимум запроса.
Для снижения нужны минимум 30 полных успешных аллокаций с корректным измерением
этого endpoint. Много запросов одного сезона не заменяют 30 аллокаций.
Без достаточных измерений сохраняется прежний bound, а при его отсутствии —
прежний бюджет класса. В v4 без нового поля загрузчик сохраняет старое поведение.

Оба значения в JSON записаны **до надбавки 15%**. Существующие
`allocation_budget_bytes()` и `_with_allocation_headroom()` добавляют её ровно
один раз при построении подписанного плана и локального бюджета соответственно.
Сам пересчёт надбавку не добавляет. Отдельный bound запроса ограничивает одну
резервацию; оставшийся расход аллокации может дополнительно уменьшить её.

## Ограничения данных и воспроизведение

Старые ledger записи уплотнены штатным механизмом #1350: `units` и `lease_stats`
удалены. Полнота сезонной аллокации восстановима по контракту одного сезона.
Размер старого пакета матчей или игроков неизвестен; его расход не доказывает
полный пакет и не используется для снижения бюджета. В выборке исключены
13 259 частичных пакетов или записей с неизвестным размером, 4 242 незавершённые
либо нулевые аллокации и 6 155 аллокаций вне временного условия.
Request maps сохранились преимущественно за последние дни. Отсутствующие
измерения не выданы за полные 30 суток и не заменены экстраполяцией.

Локальные доказательства находятся в основной копии проекта:
`.local/tasks/1365/budget/`. `snapshot-manifest.json` содержит исходные пути,
SHA-256 исходных файлов и очищенных снимков. Снимки содержат только метрики;
состав пакета заменён числом элементов, подписи и секреты исключены.
`baseline-policy.json` сохраняет исходную политику;
`calibration-report.json` содержит количество наблюдений, максимумы,
сохранённые границы и SHA-256 входов. Эти локальные снимки не входят в Git.

Запуск из worktree с `--policy` исходного файла и тремя `--ledger` снимками:

```bash
python -m scripts.research.calibrate_sofascore_workload_policy \
  --policy <baseline-policy.json> \
  --ledger <gateway-state-allocations-sanitized.json> \
  --ledger <gateway-state-history-allocations-sanitized.json> \
  --ledger <gateway-state-players-allocations-sanitized.json> \
  --as-of 2026-10-09T12:19:14.849751+00:00 \
  --output-policy <candidate-policy.json> \
  --output-report <calibration-report.json>
```

Результат воспроизводится без Airflow, браузера и сетевых обращений.
Новая статическая политика сама по себе не подтверждает production-приёмку.
