# Составы через 14 дней после доставки (#1330)

Показатель равен доле сыгранных матчей FBref, у которых в `bronze.fbref_lineups` к концу окна ноль строк. Взрослые мужские турниры и текущие сезоны берутся из того же реестра, что и в суточной сводке. Учитываются матчи с реальным счётом, в том числе 0:0 и турниры, где источник публикует только результат. Единица счёта — матч, независимо от количества игроков или повторных наблюдений. [Правила суточной сводки](fbref-daily-report-1323.md)

1. Возьмите SHA и время фактической доставки из квитанции проверенной рабочей ревизии. Начало окна `DEPLOYED_AT` включительно, `CUTOFF = DEPLOYED_AT + 14 × 24 часа` исключительно по времени начала матча в UTC. Состояние составов проверяется на `CUTOFF`. После доставки в середине суток в окно входят части двух пограничных дат.
2. Сохраните исходный JSON-снимок суточного отчёта на `CUTOFF`. Его `coverage` должен покрывать обе граничные даты. Для частичного последнего дня используйте `collect_snapshot(host_postgres, host_trino, day=cutoff.date(), as_of=cutoff, mapping=mapping, lookback=15)` из [суточного reader](../../scrapers/fbref/daily_report_reader.py) с функциями чтения и картой из [штатного отчёта](../../scripts/report_fbref_daily.py). Он обращается к хранилищам собранных данных. Если снимок уже есть, используйте сохранённые байты.
3. На том же срезе сохраните JSON из [SELECT прямых матчей](sql/fbref_lineups_day14_direct.sql) в `direct.json`. Результат с пустым `editions` подтверждает отсутствие таких сезонов. Добавьте в корень `as_of` с точным UTC-временем среза, `snapshot_sha256` от байтов суточного снимка и `cutoff_receipt` со ссылкой на доказательство среза обоих хранилищ. Реестр и расписание в штатном reader изменяемы. Квитанция должна подтверждать состояние на границе окна, например сохранённый на границе снимок с проверкой отсутствия промежуточных записей или чтение восстановленной копии на эту отметку. При позднем чтении одно значение аргумента `--as-of` такого доказательства не даёт. При отсутствии подтверждения передайте пустой `cutoff_receipt`. При отсутствии снимка прямого реестра для предварительного расчёта передайте `{}` как `direct.json`.
4. Для каждой текущей взрослой прямой серии сверьте список матчей с ровно той сохранённой страницей турнира, на которую ссылается `catalog_source`. Сохраните в её элементе `catalog_raw_key` и `catalog_match_ids` со всеми ID этого сезона с исходной страницы. Для матча без подтверждённого статуса и UTC-времени в суточном снимке приложите в `match_proofs` запись с `match_id`, `raw_key`, `fetched_at`, `kickoff_at`, `score` и `notes` из сохранённой страницы матча. Её `raw_key` должен совпасть с последней принятой версией в `targets` этого среза. Используйте явное UTC-время либо метку с часовым поясом. Только названия команд, местная дата или время получения страницы не устанавливают момент начала матча. Отсутствие даты, непроверенный список прямой серии и неоднозначный статус остаются пробелами.
5. Создайте запрос в рабочей копии. Запустите полученный файл в Trino в режиме чтения и сохраните его вместе с результатом, обоими входными файлами и квитанцией доставки. Команда подготовки читает только локальные файлы.

```bash
python3 -B scripts/report_fbref_lineup_coverage.py \
  --snapshot "$SNAPSHOT_JSON" --control "$DIRECT_JSON" \
  --deployment-sha "$DEPLOYMENT_SHA" --deployed-at "$DEPLOYED_AT" \
  --cutoff "$CUTOFF" > lineups-day14.sql
```

Запрос читает составы, доступность и расписание в Iceberg через `FOR TIMESTAMP AS OF`. Каждая строка матча в знаменателе сохраняется при отсутствии строк состава и при отсутствии отчёта. Для строки без ID отчёта используется сочетание турнира, сезона, даты, времени и названий обеих команд. Неопределённые пограничные даты остаются в предварительном подсчёте. Наблюдение с неполной квитанцией завершения или неподтверждённым временем начала остаётся в предварительной выборке, когда матч может относиться к окну. Сыгранное наблюдение при строке расписания без результата требует сверки. Для обычного турнира то же относится к отсутствию строки. Для прямой серии полный исходный каталог и датированное наблюдение завершения с ключом сохранённой страницы подтверждают матч, даже если обход пропустил его цель.

`played` — размер выборки, `empty_lineups` — число матчей без строк в своём турнире и сезоне. `empty_fixtures` позволяет проверить каждый такой матч. `unreported` и `unverified` показывают отсутствие ID отчёта и несовпадение физической записи со статусом состава и партией записи. `unverified_fixtures` перечисляет такие матчи. `issues` перечисляет пробелы выборки. Сыгранная строка другого сезона взрослого турнира в окне требует сверки его текущей редакции и псевдонимов. Дополнительная проверка `undated_scored_rows` показывает сыгранные строки Bronze, которые выпали из чтения по дате. Такие строки требуют привязки к периоду по исходной странице. При полном срезе и ненулевом знаменателе проверка `100 × empty_lineups ≤ played` даёт `PASS` или `FAIL` без округления. Любой открытый пробел даёт `PRELIMINARY`. Недоступная историческая версия таблицы или ошибка SELECT оставляет приёмку неподтверждённой. Процент с такого среза не переносится в квитанцию успешной приёмки.
