# Transfermarkt current по сигналам (#1393)

Новый путь сохраняет один `dag_ingest_transfermarkt`, один последовательный
Bronze writer и действующие лимиты источника. Он включается только после
квалификации tmapi. До появления валидного
`dags/configs/transfermarkt/current_signal_qualification.json` работает прежний
daily schedule. Некорректный файл квалификации останавливает активацию.
Файл квалификации не входит в первоначальную поставку кода.

## Обработка

В каждой порции планировщик чередует свежие проверки и продолжение работы.
Все обращения, повторы, запись и проверка Bronze имеют общий срок до 45 минут
от начала DagRun. Preflight и чтение реестра тоже ограничены этим сроком,
включая каждый HTTP-запрос Trino. Ошибка planning завершает qualified current
задачу без внутреннего повторного запуска; следующая continuous порция
повторяет проверку. Ручной и прежний scheduled путь сохраняют свои условия.
Холодная очередь начинает с GB1, ES1, IT1, L1, FR1, затем
использует числовой уровень лиги. Ошибка scope сохраняется как его остаток,
успешные записи других scopes сохраняются.

Ежедневные проверки планируются с запасом через 20 часов. Для процента свежести
используется граница 24 часа и исходное время source raw:

1. Листинг издания даёт набор участников и подписи строк клубов.
   Для participant API сохраняется проверка `/teilnehmer/`, включая прежние
   предохранители пустого состава и идентичности издания.
2. `/players?ids[]` проверяет полную известную выборку состава пакетами до 300 ID.
   Стоимость, дата оценки, контракт, назначения клуба, агент и номер входят
   в подпись. Отсутствие оценки не разрешает пропуск истории стоимости.
3. Применимая страница травм сохраняется как raw и ops-сигнал.
   Это не новый набор истории травм из #1410.
4. Изменение назначает проверку затронутых клубов. Запись состава использует
   полный набор memberships и контрактов издания; прежние полные поля
   `/plus/1` и 90% guards сохраняются. Атрибуты обновляются для прочитанных клубов.
5. Новые игроки получают обе карьеры, изменение оценки — историю стоимости,
   изменение клуба или роли/начала профессионального назначения — историю
   переходов. Контракт сам по себе не требует карьеры.
   Недельный обход всех составов выявляет пропущенные изменения и оставляет
   карьерные обновления следующей порции.

Первый пакетный сигнал сверяется с подтверждённым Bronze baseline. Совпадение
не создаёт искусственное событие изменения. Новая дата оценки при той же сумме
сверяется с физической историей стоимости. NationalTeam назначения не
подменяются профессиональным текущим клубом. Отсутствие national assignment
не доказывает уход из старого состава: его membership проверяет listing/plus1,
а tmapi остаётся глобальным сигналом игрока с явным ограничением доказательства.
Контрактная применимость остаётся прежней. Существующий 28-дневный TTL тренеров
сохраняется; staff detector #1396
сюда не входит.

## Продолжение и предохранители

Свежие сигналы и continuation имеют разные поколения кэша. Листинги,
пакеты игроков и травмы предыдущих суток по МСК не используются как свежие
сигналы. Повтор в том же цикле может воспроизвести проверенный raw. Один
дневной packet raw может обслужить несколько изданий с явной ссылкой на
первоначальный scope; его время не обновляется и оплаченный трафик не удваивается.

#1658 сохраняется: незавершённый полный состав использует проверенные squad
страницы моложе 48 часов от исходного получения. URL, scope, body hash,
attempt chain, club generation и полные parsed rows проверяются. Старые попытки
передаются через `cache_sources`, отдельно от новых оплаченных попыток.
Для старого checkpoint v3 сохраняется исходный счётчик попыток. Если доступно
только доказательство последнего успешного ответа, отдельный legacy proof явно
показывает число доказанных попыток и неизвестный префикс. Такая запись остаётся
v3; она не выдаётся за полную цепочку v4. Новые v4 проверяются строго.

#1652 сохраняется: processed player имеет полную карьеру, остаток содержит
точные deferred IDs. Повторные операции внутри порции не обнуляют entity caps.
Новая порция получает новый child grant; закрытые grants и их трафик остаются
в доказательствах. Неучтённый незакрытый grant блокирует новый платный запрос
этого scope до сверки gateway evidence.

Факт сигнала и его обработка разделены. Только проверка физических строк,
native/dual manifests и исходной lineage разрешает применить подпись. Частичный
состав и локальный checkpoint сами по себе не подтверждают успешную запись.
Если свежий tmapi и `/plus/1` противоречат друг другу, подпись остаётся pending;
повторно читаются только противоречащие страницы. Старая непустая ceapi история
также не подтверждает новую известную оценку. Для injury есть отдельное
подтверждение `raw_durable`: оно доказывает сохранённый объект raw, не создаёт
новый parsed dataset и не требует лишнего скачивания состава.
До первого изменения Bronze журнал сохраняет точный план записи с полным
raw-подтверждённым составом. Если запись или подтверждение оборвалось, следующая
порция проверяет этот план и повторяет весь набор записи с исходной идентичностью.
Для такого завершения проверяется уже полный план записи, включая неизменяемый raw,
полные разобранные строки и цепочки попыток. Исходные fetched_at и время записи
сохраняются даже после простоя дольше48ч. Это завершение начатой записи; правило48ч
для повторного использования страниц незавершённого сбора остаётся прежним.
После восстановления обязательны свежие сигналы до дальнейших обновлений.
Восстановление не продлевает время ежедневных проверок. Подпись применяется только
после успешного read-back и manifests; старый baseline не отключается для
произвольного или повреждённого checkpoint.
Business receipts текущего пути не объявляют старый семисущностный scope
завершённым и не разрешают Silver cutover.

Локальное состояние — вспомогательный журнал под
`/opt/airflow/logs/transfermarkt-native-v2/current`: лёгкий cursor index,
отдельные scope journals и дневные packet references. Декодированные HTML/JSON
тела в checkpoint не дублируются. Неизвестная версия состояния требует явной
миграции. Единственный writer защищён файловым lock и Airflow concurrency=1.

Ранее собранные издания требуют проверенного warm baseline до активации.
Импорт проверяет полный прежний ScopeManifest, физические строки и ops;
старые даты сохраняются, daily checks остаются незаполненными. Наличие Bronze
без такого доказательства выдаёт `baseline_required`, вместо скрытого повторного
холодного обхода карьер. Число 52 из issue не считается доказательством количества
готовых scopes. Неполный прежний сбор требует отдельного подтверждённого остатка.

## Интерфейс для измерителя #1395

`iceberg.ops.transfermarkt_current_checks_v1` содержит scope/check/cycle,
registry snapshot, denominator hash, checked_at, status/result, raw references,
expected/observed IDs. `complete` разрешён только при полной проверке; ошибка
не продлевает свежесть. Измеритель соединяет проверки с текущими edition IDs
promoted registry. Заблокированные и отсутствующие соревнования остаются
в знаменателе; новые eligible соревнования вне файла обрабатываются как tail.

`iceberg.ops.transfermarkt_current_signals_v1` содержит observed/applied
signature, first_detected_at, last_checked_at, signal version, исходный raw
capture/hash/URL/fetched_at, status/result, Bronze manifest и committed_at.
Superseded failures сохраняются в JSON evidence. Неизменённый повторный сигнал
не сдвигает first_detected и не стирает ошибку. Устаревшее подтверждение не может
применить более новую подпись.

Portion reports предоставляют текущий target set и блокировки, независимые
результаты scopes и трафик grants. Для проверки нужны raw attempts, cache_sources
и business receipts с физическими hashes. Разделять cold, change, weekly,
retry и cache hit. Успех порции не является доказательством 100% покрытия суток.
`first_detected_at` — время обнаружения нашим сборщиком; site first_seen и
контрольную выборку изменений определяет #1395.

Приёмка: 100% живых текущих изданий три дня подряд; >=99% обнаруженных изменений
в Bronze за 24 часа; ноль повторных скачиваний составов без изменения сигнала
(недельную страховку учитывать отдельно). До 100 МБ/сутки вне cold — измеряемая
цель, суточный hard cap не вводится. Это не реализация измерителя #1395 или
глобального карьерного долга #1394.

## Квалификация и доставка

Ограниченный инструмент `dags/scripts/bench_transfermarkt_signals.py` использует
настоящие source parsers, HTTP client и raw store, но не Bronze writer.
Он требует tmapi schema probe, затем свежую текущую клубную выборку >=1000 IDs,
полный `/plus/1`, оба ceapi и два наблюдения одной выборки. Квалификация проверяет
содержимое сравнений, missing/unknown, даты, source raw proofs и реальные
изменённые поля, видимые reference и tmapi в один день. Одних флагов true,
зелёных unit-тестов или старого raw недостаточно.

Согласованный эксперимент ограничен суммарно 4600 оплаченными попытками и
256 МиБ provider bytes, включая повторы и оба дня; <=12 попыток/мин, один поток,
<=45 минут на порцию. Raw остаётся в материалах задачи. Перед каждой порцией
проверить idle штатных ingest/discover. Прерванный active lease требует сверки,
не сброса marker. Configured sample scopes и участие клуба в указанном сезоне
не доказывают актуальность издания promoted registry или runtime coverage.

Окно доставки остаётся 04–06 МСК (01–03 UTC). Source timetable plugin не
создаёт новые порции 00:15–03 UTC; runtime повторяет проверку admission для
поздно стартовавшей задачи. Пустые/короткие порции имеют минимальный интервал
пять минут, полная порция продолжает работу сразу. Manual/force сохраняет
прежние one-shot approvals и timeout 5ч15м, без общего DAG timeout 45 минут.
Deployment recipe указывает только папку TM plugin.

Порядок: код и тесты → отдельное Codex-ревью → PR → фактическая квалификация
и проверенный baseline → файл активации → отдельная команда merge → штатная
автодоставка → метабаза scheduler/mounts/fingerprints → трёхдневная runtime-приёмка.
Если tmapi не проходит квалификацию, активация останавливается; замена
ежедневного второго сигнала недельным обходом требует решения владельца.
History/backfill и Silver не включаются. Для отката использовать прежнее
принятое release по существующему регламенту, без ручной доставки в этой задаче.
