# TRINO-GRILL — 2026-10-29 (10:30 МСК)

Тема: общий Trino под 8 параллельными парсерами (bronze) и стартующим silver.
Повод: «кажется, в последнее время много ошибок, связанных с Trino».

## Если по-простому

Сама конфигурация Trino в порядке. Ошибки идут от того, что один сервер Trino с 5 ГБ памяти под
запросы обслуживает все 8 парсеров сразу и захлёбывается. Все 6 перезапусков с 28.09 — одна
причина: нехватка памяти Java при записи SofaScore в таблицу, раздробленную на ~130 тысяч мелких
файлов. Корень класса — мелкие файлы по всему bronze (60 таблиц, ~759 тыс. файлов), ночная
склейка почти не работает. Решили: поднять память Trino (ночной перезапуск), склеить файлы
первыми (silver на паузе до конца склейки), дать каждому источнику своего пользователя Trino с
лимитом памяти, запретить в общем коде записи MERGE без фильтра партиций, железо пока не покупать.

## Решения владельца (29.10)

1. **Решено: поднять Trino до 20 ГБ контейнера и 10 ГБ heap**, перезапуск в ночное окно;
   тюнинг закоммитить в master (переоткрыть/пересобрать #1235), чтобы не потерялся при
   пересоздании.
2. **Решено: железо не покупаем.** Сначала склейка и память; замер нагрузки через 2 недели
   (≈ 12.11.2026). Если load > 32 на 16 ядрах после склейки — прийти с цифрами и ценой второй
   VM под Trino (вторая VM — правильная прод-архитектура, следующий этап, не сейчас).
3. **Решено: склейка первая, silver на паузе до её конца.** Код silver не пишем/не гоняем,
   пока #1892/#1879 не закрыты.
4. **Решено: каждому источнику свой пользователь Trino + лимит памяти на запрос** (resource
   group на источник). Внедряется вместе с ночным перезапуском из п.1; источники переводятся по
   одному, `airflow` остаётся рабочим.
5. **Решено: запрет MERGE без фильтра партиций — в общем коде записи**
   (`scrapers/base/trino_manager.py`), класс целиком; пломбу WhoScored переставить по его
   регламенту; ревью ≤3 раунда.
6. **Решено: критерий «сдано» для стабилизации Trino:** 14 дней RestartCount не растёт +
   RSS < 80 % лимита + `count(*)` по самой тяжёлой bronze-таблице ≤ 10 с. Отсчёт — с ночного
   перезапуска п.1. Смотрит утренний сторож (строка «Trino»: перезапуски, память, число файлов
   топ-таблиц) — делается без вопроса.
7. **Решено: три старых преобразования (Capology silver, SoFIFA silver, FBref gold) — на паузу**
   до конца склейки.
8. **Решено: ночное окно склейки 03:00–05:00 МСК**, парсеры держат запись и дописывают после
   (замок таблицы / ожидание конца окна). Цель «99 % ≤ 24 ч» этим не нарушается.

## Канон, НЕ переспрашивать

- Память Trino 20 ГБ / heap 10 ГБ — решено; перезапуск только в ночное окно.
- Вторая VM / расширение — не раньше замера 12.11; без цифр не поднимать.
- Silver (новый и три старых DAG) стоит, пока bronze не склеен.
- Пользователь Trino на источник + лимит памяти — делать.
- Общий код записи править можно (с переставлением пломбы WhoScored).
- Окно склейки 03:00–05:00 МСК — парсеры ждут.
- Критерий сдачи — три числа из п.6.
