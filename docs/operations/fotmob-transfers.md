# FotMob: ежедневные трансферы (#1296)

Оркестратор выделяет трансферам окно 00:00–02:00 UTC (03:00–05:00 МСК).
Он запускает существующий `dag_ingest_fotmob` с `mode=transfers`, только после
проверки свободного писателя. Новый запуск требует не менее 15 минут до дедлайна.
Успешный полный обход либо исчерпание бюджета освобождает остаток окна фоновым
полосам. Окно матчей DAILY, его лимиты и исторический режим не изменяются.

Трансферы получают отдельный суточный бюджет: 6000 запросов, 512 МиБ прямого
трафика, 0 прокси, до 60 запросов в минуту. Повторы расходуют остаток того же
бюджета. Размер последнего HTTP-ответа проверяется после получения тела, как в
существующем транспорте: превышение лимита байтов делает результат ошибочным и
исчерпывает бюджет; это не строгий сетевой лимит размера ответа.

Полоса обновляет каталог и доказательства included-классификации, затем собирает
потоки трансферов за год, начиная с наиболее давно проверенных турниров.
Полный пустой поток считается успешной проверкой. Частичная пагинация, ошибка
парсинга либо неуспешная запись Bronze не обновляют время полного сбора.
Ответ из старого кеша после ошибки FotMob не подтверждает свежесть. При повторе
используются только успешно проверенные в эти сутки страницы; stale-checkpoint
отбрасывается, даже если чтение его raw-файла само по себе прошло успешно.
События остаются в `fotmob_transfer_events`; фиктивных строк для пустых потоков
нет. Подтверждение полного сбора хранится отдельно от дат самих трансферов.

Учёт суточного бюджета и зеркало подтверждённой свежести сохраняются в
`/opt/airflow/logs/fotmob-transfers.sqlite3`. Переменная
`FOTMOB_TRANSFER_STATE_PATH` позволяет выбрать путь в изолированных тестах.
Рабочий путь должен находиться на существующем постоянном томе logs. Потерянную
или повреждённую базу нельзя удалять ради нового бюджета. При аварии без
подтверждённого окончания зарезервированный бюджет не возвращается автоматически.

Перед выбором следующей полосы оркестратор публикует в лог и XCom строку
`family_summary`: включённые, свежие, просроченные и непроверенные турниры,
максимальный возраст и цвет статуса. Возраст строго больше 48 часов хотя бы у
одного included-турнира делает строку красной. Отсутствие или устаревание
доказательств каталога также исключает зелёный статус. Ровно 48 часов ещё не
превышают порог. Проверка не выполняет запросов к FotMob и не запускает сбор.

## Доставка и приёмка

PR по #1296 готовит код; merge и доставка требуют отдельных разрешений владельца.
Не менять текущие пины, автомат доставки, cron, сторожей, hold/STOP или #1185.
Не возобновлять историю и не выполнять ручной ingest для проверки.

После отдельно разрешённой доставки проверить перечитывание DAG в метабазе
Airflow, отсутствие import errors, суточный обход included-набора и сохранённые
completion-маркеры Bronze. Отдельно подтвердить, что трансферная полоса не
вытесняет матчи. Успех Python-тестов либо зелёный частичный DagRun не заменяет
эту приёмку. Серию #1296 учитывать отдельно от текущих #1288/#1289; issue до
выполнения её критериев остаётся открытой.

При откате кода сохранять файл учёта трансферов: он содержит уже потраченный
суточный бюджет. Формат `fotmob.scheduler.state.v1` остаётся прежним.
