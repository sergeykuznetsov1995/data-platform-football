# Разовая миграция фантомных сезонов FotMob (#1231 / #1288)

`scripts/fotmob_repair_seasons.py` удаляет только проверенные старые физические
строки `fotmob_competition_seasons`. Представление `_current` перестаёт видеть эти
строки естественным образом. Определение представления, история сезонов, manifest,
матчи и версия парсера не изменяются. Инструмент не вызывает общий cleanup,
scheduler, доставку или источник FotMob.

## Что нужно доказать до запуска

Исходное расследование указывает **49 меток**, а не 49 физических строк:
337 — 17, 335 — 12, 274 — 11, 230 — 9. Эти числа задают верхнюю границу, а не
автоматический список для удаления. Допустим проверенный поднабор. Список точных
меток и всех их физических batch должен быть подготовлен и отдельно проверен
по доказательствам #1231. В репозитории такого production-списка нет; придумывать
его по годам или выбирать все bare-метки нельзя.

Для каждой метки нужны:

- Exact `competition_id` и `source_season_key` без нормализации.
- Все старые `_target_batch_id`, `_payload_sha256`, `_raw_uri` этой метки и
  сохранённые локальные bytes соответствующих raw catalog payload.
- Сохранённый актуальный raw catalog того же турнира и его SHA-256/URI.
  Фазовая метка должна присутствовать в `_current` с тем же SHA-256/URI.

Инструмент сам проверяет SHA-256 bytes и заново вызывает `parse_seasons`.
В старом raw bare-метка должна находиться во вторичных stats-списках; текущий
парсер должен исключать её и сохранять соответствующую Apertura или Clausura.
Актуальный catalog также должен исключать bare-метку и включать фазовую.
Bare-метка, сохранённая в `allAvailableSeasons`, считается самостоятельным
сезоном и блокирует удаление. Совпадения префикса недостаточно.

Пример **формата**, не готовое production-доказательство:

```json
{
  "issue": 1231,
  "catalogs": [{
    "competition_id": 337,
    "path": "/reviewed/current-337.json",
    "sha256": "SHA256_OF_EXACT_BYTES",
    "raw_uri": "s3://reviewed/current-337.json"
  }],
  "targets": [{
    "competition_id": 337,
    "source_season_key": "EXACT_REVIEWED_BARE_LABEL",
    "provenance": [{
      "batch_id": "EXACT_OLD_TARGET_BATCH_ID",
      "path": "/reviewed/old-337.json",
      "sha256": "SHA256_OF_EXACT_OLD_BYTES",
      "raw_uri": "s3://reviewed/old-337.json"
    }]
  }]
}
```

## Dry-run и резервная копия

Требуется уже настроенное Trino-окружение (`TRINO_HOST` и штатные параметры
подключения). Скрипт не загружает `.env`. Запускать из проверенной отдельной копии.
`plan` выполняет только SELECT/DESCRIBE; доступ к БД всё равно требует разрешения.

```bash
python scripts/fotmob_repair_seasons.py plan \
  --manifest /reviewed/exact-keys.json \
  --plan /reviewed/repair-plan.json --catalog iceberg --schema bronze
```

План содержит полные удаляемые строки всех физических версий, имена/типы колонок,
raw-доказательства, exact provenance, версию парсера и контрольную сумму. Он
создаётся эксклюзивно с правами 0600; существующий файл не перезаписывается.
Запись и каталог синхронизируются на диск до завершения команды. Перед apply
сохранить проверенную копию вне локальной рабочей области: `.local/` не является
резервным хранилищем. Проверить число ключей, число строк, назначения catalog/schema
и Trino host. Контрольная сумма защищает от случайного изменения, не заменяет ревью.

Поддерживаются скалярные SQL-типы, которые Trino сохраняет без потери через
VARCHAR: строки, boolean, целые/вещественные, decimal, date, timestamp.
Неизвестные/вложенные типы блокируют план. SQL-интеграция с реальным Trino/Iceberg
должна быть проверена перед production: offline-тесты не подтверждают её.

## Применение и откат — отдельные явные действия

Production apply/rollback требуют отдельного разрешения. Настоящий документ и
готовность кода такого разрешения не дают. #1185, #1287, delivery pin, campaign
hold, STOP и общий scheduler этой задачей не меняются.

До любой мутации оператор обязан обеспечить и проверить **эксклюзивное окно
без писателей** в эту таблицу и без другого запуска миграции. Оно должно
продолжаться до проверки результата. `--writers-quiesced` — явное утверждение
этого внешнего условия, не автоматическая проверка и не команда остановки.
В Trino/Iceberg проверки и последующий DML не объединяются транзакцией.
Нельзя применять инструмент одновременно с ingest/reconcile/compaction или
другой миграцией. Смена host между plan и apply также недопустима.

```bash
python scripts/fotmob_repair_seasons.py apply \
  --plan /reviewed/repair-plan.json --writers-quiesced
python scripts/fotmob_repair_seasons.py rollback \
  --plan /reviewed/repair-plan.json --writers-quiesced
```

Apply повторно проверяет доказательства, типы, **весь** физический набор строк и
актуальный catalog в `_current`. Он выполняет один атомарный DELETE с равенством
всех сохранённых колонок и проверяет отсутствие целевых строк. Законные bare-сезоны
и фазовые строки не входят в DELETE. Manifest старых batch остаётся историческим:
после миграции его счётчик больше не равен физическим строкам. Старый writer/parser
и replay этих старых batch должны оставаться выключены; повторный запуск старого
reconcile не входит в миграцию и может восстанавливать удалённое или выдавать ошибку.

Rollback работает из того же плана и версии кода. Если весь исходный набор уже
присутствует, результат `already_restored`; если отсутствует полностью — один
атомарный INSERT восстанавливает все колонки, NULL, provenance и дубликаты.
Любое частичное состояние или новые/изменённые строки целевых ключей блокируют
и apply, и rollback до отдельного разбора. Применение после успешного применения
возвращает `already_applied`. Потеря ответа после завершённого DML допускает
безопасный повтор той же команды после выяснения, что исходный запрос завершён.

После apply проверить отсутствие всех целевых ключей в physical/current,
сохранность фазовых и законных bare-сезонов, неизменность history/manifest и
результат штатного чтения каталога. До этой приёмки сохранять окно и backup.
Сбой постусловия требует сохранить backup и окно; не запускать общий cleanup.

## Проверки разработки

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q -p no:cacheprovider \
  tests/unit/scripts/test_fotmob_repair_seasons.py
```

Offline-тесты выполняют реальные DELETE/INSERT в SQLite и проверяют dry-run,
provenance, законные bare-метки, дрейф строк/catalog, потерю ответа, дубликаты,
NULL, откат и повторные запуски. SQLite подменяет только DESCRIBE и квалификатор
catalog; эти тесты не доказывают транзакционность или типовую совместимость
production Trino/Iceberg. Production-план, apply и rollback при разработке не
выполнялись.
