# Чек-лист «источник в проде»

Живой документ. Согласован 2026-07-31 (черновик v1 — грилинг-аудит 2026-07-28).
Обновлять при каждом релизе/деплое источника: правишь клетку матрицы в том же PR,
которым меняешь состояние источника.

Правило: источник считается «в проде», только когда **все 7 пунктов зелёные**.
Пока хотя бы один красный — источник «в доводке», и у него должен быть один
следующий шаг (не список из десяти).

## 7 пунктов

| № | Критерий | Как проверяется |
|---|---|---|
| 1 | **Данные едут сами**: daily-DAG включён и ≥3 дня подряд зелёный без ручных пинков | Airflow: 3 последних рана success |
| 2 | **Доезжают до витрин**: свежий bronze появляется в gold в течение суток | max(committed_at) витрин двигается вслед за bronze |
| 3 | **Код сохранён**: всё, что крутится на проде, закоммичено и влито в master | git status деревьев чист; прод монтирует master/влитую ветку |
| 4 | **CI-гейт**: unit-тесты источника гоняются на каждом PR | .github/workflows: workflow есть и зелёный |
| 5 | **Поломка приходит сама**: TG-алерт на красный ран и на свежесть >48 ч | сторож-агент / алертинг, без «ну что там» |
| 6 | **Трафик замерен**: ГБ/мес известны из фактических (billed) байт и вписаны в бюджет | ops.proxy_traffic_runs + отчёт 02:00 |
| 7 | **Закрыто по-взрослому**: runbook на 1 страницу (перезапуск, мины, статус), issue закрыта, доска обновлена | docs/operations/ + доска |
