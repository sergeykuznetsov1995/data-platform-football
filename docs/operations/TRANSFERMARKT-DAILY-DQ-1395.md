# Ежедневный Bronze DQ Transfermarkt (#1395)

`daily_bronze_dq` — независимая корневая задача существующего ingest DAG.
Она использует `transfermarkt_control`, читает Trino и сохраняет локальный
отчёт. Проверка не требует квалификации current, approval paid traffic или
успешного ingest. Таймаут — 10 минут, один retry через 5 минут: суммарное
окно двух попыток не превышает 25 минут и сохраняет ограничение current
45 минут. Новых DAG, cron, paid I/O и записей в Bronze/Silver/Gold нет.

## Контракт выполнения

`utils.transfermarkt_daily_dq.run_daily_bronze_dq(cursor, state_root=...,
run_id=..., now=...)` выполняет полный `run_bronze_dq(zone='full')` один раз
за сутки МСК. `now` — часы исполнения, а не логическая дата старого DagRun.
В production `now` не передаётся и берётся из текущих UTC часов.

Каталог по умолчанию:
`/opt/airflow/logs/transfermarkt-native-v2/daily-dq`.
`implementation.json` закрепляет время первого фактического исполнения
нового кода. Это консервативная граница проверки новых строк, а не
восстановленное время выкладки. Она не задаётся исторической константой и не
изменяется при следующем дневном аудите. Строка относится к новой когорте,
если `_ingested_at` или `fetched_at` достигает этой границы.

Локальный `flock` исключает два аудита одних суток. Отчёт `<YYYY-MM-DD>.json`
и каждый файл `attempts/` записываются атомарно. Завершённый `RED` сохраняет
красный статус и не повторяет полный sweep при следующих порциях current.
Ошибка SQL оставляет `completed=false`; следующий вызов повторяет аудит.
Падение процесса до сохранения также не создаёт завершённого результата.

Все native и legacy Bronze, входы опубликованного реестра и ops-доказательства
фиксируются Iceberg snapshot IDs, существовавшими к `cutoff_at`. Отсутствие
снимка — неполная проверка, а не разрешение читать изменяемую таблицу.

## Доказательства и пороги

Результат содержит `version`, `day_msk`, `run_id`, `cutoff_at`,
`implementation_at`, `input_snapshot_ids`, `completed`, `status`, `checks`,
`metrics`, `errors`, `execution_errors` и `paid_requests=0`.

- `metrics.fields`: число применимых и заполненных полей и их отношение.
  Для contract observations исключается `not_applicable`; для числовых fee
  и market value применимость связывается с имеющимся исходным текстом.
  `not_applicable_or_unknown` не является заполненным значением. Заполненность
  остальных полей описательная; числовые пороги не придуманы.
- `metrics.cohorts`: старая/legacy когорта, строки после фактической границы,
  неизвестные часы и NULL lineage. Для всех девяти native таблиц NULL хотя
  бы одного обязательного lineage-поля в новой когорте даёт `RED` при >0.
  Legacy и строки до границы не выдаются за новые корректные строки.
- `metrics.first_seen`: для четырёх таблиц first_seen проверяется заполненность
  у новых строк и равенство всех ненулевых first_seen неизменяемому ops-реестру
  по естественному ключу.
  Ключи берутся из helper writer, включая NULL-safe дату окончания тренерского
  срока. Если nullable колонка ещё не создана первым write или ops-реестра нет
  к cutoff, результат этой метрики UNKNOWN; полный аудит продолжается.
  NULL first_seen в новой когорте и несовпадение с реестром дают RED.
- `metrics.empty_by_route`: последняя complete-проверка listing каждого
  издания, сгруппированная по `route` файла-знаменателя #1390. У `pokal`
  доля `authoritative_empty` строго выше 5% даёт `RED`; отсутствие исхода
  остаётся unknown. Нулевой знаменатель даёт NULL отношения.
- `metrics.career_debt`: существующее доказательство долга career fetches и
  число manifests без него. Очередь и алгоритм #1394 не меняются.
- Ноль считается подменой неизвестного только при исходном `mv_raw` или
  `fee_text` из явного множества `-`, `—`, `?`, `n/a`, `unknown`.
  `fee_eur=0` для реального free transfer разрешён. NULL исходного текста не
  доказывает подмену нулём. Существующие проверки дублей и потерь сохраняются.

`RED` означает подтверждённое нарушение. `UNKNOWN` означает неполные или
неизвестные доказательства; отсутствие карьерного/route evidence и неизвестные
часы не превращаются в `GREEN`. Завершённый `UNKNOWN` может быть перечитан
без повторного sweep. Подтверждённый RED при сбое другой проверки
сохраняется в сводке с пометкой «неполная проверка». Следующий день всегда
получает новый аудит.

`read_daily_result(state_root=..., now=...)` возвращает `stale=true` и
`UNKNOWN`, если результата текущих суток нет или версия устарела.
`format_daily_dq_summary(report)` даёт общую строку для сводки. Подключение
живого watchdog, production-запуск и runtime-приёмка требуют отдельного
согласованного запуска; наличие кода не является их доказательством.
