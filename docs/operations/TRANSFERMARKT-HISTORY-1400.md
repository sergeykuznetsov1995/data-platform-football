# Исторические порции Transfermarkt (#1400)

История выключена по умолчанию: `TM_HISTORY_STREAMS=0`. Конфигурация
`TransfermarktStreams` задаёт один current поток и отдельную ёмкость истории.
Airflow init, deploy и приёмка используют тот же Python helper для размеров
`transfermarkt_control`, `transfermarkt_proxy`, `transfermarkt_backfill_control`
и `transfermarkt_backfill_proxy`. Общий `ingest_scraper_pool` не участвует.
Изменение файлов рецепта не включает историю и не подтверждает доставку.

Порция получает абсолютный срок от `DagRun.start_date`: максимум 45 минут,
включая planning, HTTP, Trino polls и ops/commit. Каждый этап использует исходный
срок, поэтому ожидание пула не даёт новый бюджет. Перед HTTP остаётся запас
на запись результатов и закрытие аренды. Аренда ограничивается оставшимся
временем порции. Новые порции не допускаются 00:15–03:00 UTC; окно доставки
04–06 МСК сохраняется. Ручной и прежний current пути сохраняют прежние
условия; квалификация #1393 не меняется.

History DAG задаёт `dagrun_timeout=45 минут`: scheduler закрывает просроченный
DagRun и помечает незавершённые queued/scheduled tasks как SKIPPED. Этот срок
не меняет прежние manual/legacy current условия 5ч15м.

Файловый журнал с `flock` резервирует максимум 500 попыток перед платным GET,
включая повторы всех mapped tasks одной порции. Резервация сохраняется до GET
и не возвращается при аварии; это консервативная верхняя граница расходов.
Она не является суточным или кампанийным лимитом. Исходные byte/entity caps,
90% guards, typed empty и native lineage остаются действующими.
`TM_HISTORY_PORTION_REQUEST_LIMIT` может только уменьшить лимит до 1–500;
`TM_HISTORY_RECOVERY_PROBE=true` фиксирует одну попытку. Такой probe принудительно
читает свежий listing, сохраняет raw и возвращает continuation. Полный ранее
проверенный players checkpoint сохраняется; probe не объявляет scope завершённым.

Полный состав сохраняется отдельным checkpoint. Карьерный пакет останавливается
до нового игрока с запасом на полный endpoint. Обработанный игрок имеет полную
карьеру. Результат содержит точные `attempted_ids`, `deferred_ids`, полный
`roster_ids` и `remaining_ids`; непрочитанный хвост не помечается ошибкой.
Успешные пакеты архивируются с неизменяемым содержимым. Следующая порция
использует исходный child/capture identity и fetch state, пропускает полный
состав и продолжает оставшиеся карьеры. Пакет с остатком не становится финальной
сущностью. `continuation` закрывает scope lease и не расходует три попытки
ошибок источника. Это локальное продолжение истории, без глобального debt/TTL
#1394. Проверенный48-часовой squad continuation #1658 остаётся только current.

Финальный карьерный receipt связывает исходные пакеты по пути и SHA256 и
подтверждает полный fingerprint по исходным `native_snapshot_id`, записанным
#1399 под общим writer lock. Batch DQ повторяет fingerprint и raw lineage
на каждом исходном snapshot. Если current уже заменил глобальную карьеру,
исходное доказательство истории сохраняется; новые строки не получают
синтетический старый scope/cycle. Проверенная snapshot presence используется
для соответствующей проверки наличия; остальные DQ guards сохраняются. Полный
scope proof сохраняет совокупный трафик пакетов; parent ledger отражает только
свою порцию, чтобы старые оплаченные пакеты не считались новым расходом.

Receipt сохраняет immutable `capture_unit_id`, logical native batch и точные
`physical_refs` каждого игрока, включая кэш с исходным physical batch другого
scope/cycle. Stable child и checkpoint пути остаются прежними. Нулевая карьера
хранит `empty_capture_refs` с исходным source clock и typed raw. Если таблицы ещё
не было, snapshot=None допустим только с этим доказательством; более поздние
current строки не превращают исходный empty в новый capture.

Закрытие после TTL сохраняет исходные portion, attempt ledger и reservation/grant;
порция, которая провела reconciliation, записывается отдельно. Rollback snapshot
сохраняет фактические пулы прежнего релиза и их размеры. При возврате к старому
дереву приёмка использует этот контракт. Она не запускает новый pool helper
в старом коде и не требует нового control pool от старого релиза.

Клиент закрывает аренду в `finally`. Приватный журнал аренды имеет права 0600.
После hard kill новая аренда этого scope запрещена до истечения старого TTL.
Затем клиент требует успешный gateway close с окончательными счётчиками;
само истечение времени не является подтверждением. Сбой сверки сохраняет
блокировку. Подтверждение закрытия хранит счётчики без credentials. Незавершённые
записи/attempt intents продолжают использовать существующую platform
reconciliation; платный replay не разрешается отсутствием результата.

Локальные тесты не заменяют runtime-приёмку: нужны три реальные партии с
checkpoint/resume и DQ, длительность задач ≤45 минут, доля незакрытых аренд <1%,
и отсутствие ожидания исторического пула у current. Платные запросы, включение,
ручная доставка и production изменения этой реализацией не выполняются.
