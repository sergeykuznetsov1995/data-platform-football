# Независимые слоты истории SofaScore (#1364)

История использует три воркера в своём Airflow pool. Каждый запускает существующий
цикл скоупа, проверяет его результат, сохраняет учёт и сразу получает следующий
доступный скоуп. Долгий турнир не задерживает переход другого турнира к следующему
сезону выбранной группы. Одновременно выполняется максимум один сезон турнира.
Явное ограничение `SOFASCORE_HISTORY_MAX_ACTIVE_TASKS` ниже трёх уменьшает число
воркеров; значение выше трёх не увеличивает параллельный захват. История по умолчанию
использует `sofascore_history_pool`, а не пул дейли.

## Порядок и восстановление

Группы, гейт99%, июльская когорта, карантин и парковка сохраняют правила
[контроллера #1363](sofascore-history-controller.md). Новый DagRun фиксирует
неизменяемую очередь всех доступных сезонов выбранной группы. Выдача идёт в порядке
контроллера; сезон занятого турнира временно пропускается. Новая группа выбирается
только в следующем DagRun по свежему фактическому долгу.

В существующем checkpoint схема1 дополнена `run.mode=slots`, неизменяемой очередью
`run.plan`, назначениями `run.slots` и журналом `run.items`. Индекс попытки отличается
от `plan_index`: первый задаёт порядок выдачи, второй указывает на элемент очереди.
Digest очереди и журнала проверяется до чтения. Блокировка, fsync и атомарная замена
сохранены. Старые незавершённые планы сначала проходят штатное восстановление по
терминальному состоянию Airflow; новые резервации не крадут живую работу.

Рестарт слота возвращает прежний скоуп, run_id, подписанный план и пути результатов.
Исход сохраняется до учёта, слот освобождается после него. Повтор фиксации отказа
с тем же run_id не увеличивает счётчик. Обычный отказ скоупа допускает один повтор
через120секунд; затем воркер учитывает отказ и продолжает очередь. Карантин остаётся
долгом. Состояние DagRun честно отражает ошибки, даже если соседние скоупы успешны.

Перед новой выдачей воркер читает паузу DAG и размер пула из Airflow. Закрытая или
неизвестная выдача не начинает новый скоуп. Скоуп ограничен четырьмя часами и остатком
шестичасового окна DagRun; последние10минут оставлены для учёта. Невыданные сезоны
не становятся отказами. Резервация, в которой захват не стартовал до закрытия выдачи,
получает `not_started` без записи отказа и без включения в долю красных попыток.
Рестарт проверяет паузу до каждого захвата, сохраняет предел двух запусков и
учитывает сохранённый успешный результат без повторного обращения к источнику. SIGTERM завершает принадлежащую воркеру группу процессов и
сохраняет исход текущего скоупа. Доставка проверяет учёт всех выданных скоупов, а не
цвет воркера0.

## Манифест и доступность

План и захват фазы скоупа используют один manifest store и один SELECT скоупа.
Повторный preload отвечает из памяти. Сезонная и матчевая фазы читают отдельно:
между ними публикуются сезонные данные. Буфер записи200 и существующая ручка
`SOFASCORE_MANIFEST_BATCH_SIZE` сохранены. Flush и canonical writer-lock не обходятся.

Реальный сохранённый404 исключает повтор только соответствующего final-матча и
эндпоинта. Отсечка по первой аллокации, создававшая synthetic not_supported для
ненаблюдавшихся матчей, удалена из production path. Старые точные synthetic записи
остаются пригодными для saved replay; usable2xx raw сохраняется.

Порог турнира — ≥95% реальных404 среди ≥20 различных final-матчей одного исходного
турнира/сезона и эндпоинта. Synthetic, неизвестные и другие freshness keys не входят
в доказательство. В отчёте выделяются три поздних матча, уже покрытые подписанными
аллокациями; их2xx снимает вывод о низкой доступности. Хронология определяется
сохранёнными timestamps или существующим порядком афиши; без доказательства явно
указывается неизвестная хронология. Порог не создаёт терминальных статусов,
не откладывает непроверенные эндпоинты и не расширяет оплаченный план.

## Метрики и оставшаяся приёмка

Worker TI не равен одному скоупу. Новый адаптер считает красные попытки по
проверяемым квитанциям `history-slots-<hash DagRun>.json` и точным отчётам скоупов.
Квитанция содержит все выданные попытки, индексы, исходы, временные метки и digest.
При неполных доказательствах история неизвестна. Старый host-потребитель без
адаптера получает явную недоступность истории; актуалка измеряется независимо.
Подключение адаптера к host-сводке и production-приёмка выполняются отдельно.

Offline-проверки доказывают порядок, восстановление, отсутствие новых запросов
при replay и сокращение чтений манифеста. Они не доказывают занятость≥78% и семь
суток≥67сезонов/≥10,1тыс.матчей в сутки. Merge, доставка, возобновление истории и
приёмка требуют отдельных шагов. #1364 не закрывается этим PR; приёмки1361/1638/1363
не изменяются.
