## Причина и изменение

`sync_transfers` раньше убирал события, уже встреченные на предыдущих страницах,
до записи текущей страницы. При смещении пагинации неизменная страница могла
дать49 или50 строк под одним ID: ID зависел отtarget/raw/parser, а набор строк
ещё и от предыдущих страниц. Строгая сверка опубликованного batch отвергала
расхождение. Guard не является причиной ошибки и сохраняется.

Теперь каждая страница записывает полный результат `parse_transfers`.
Дубликаты внутри страницы по-прежнему объединяет parser. Множество событий
по всему потоку отдельно определяет `events`, `unique_seen`, source hits и
полноту пагинации. Существующий current view устраняет повторения событий
между страницами; сумма физических строк не становится знаменателем полноты.

У полного набора страниц отдельный стабильный `observation_id` и capability
`page_row_policy=transfer-page-snapshot-v1`. Он входит в существующий алгоритм
batch ID. Это локальная версия материализации transfers; общий parser version,
natural event ID, schema и остальные target batches не меняются.
Опубликованные legacy49 строки и manifest не перезаписываются и не удаляются.
Новый batch содержит полный набор50. Для нового batch опубликованные49/50
по-прежнему означают отказ, включая повтор после потери ответа writer.

Legacy checkpoint без этой policy не считается готовым полным снимком страницы.
Следующий разрешённый запуск обрабатывает его обычным путём в прежнем бюджете.
Новые checkpoints сохраняют текущие raw resume, anchor, freshness и page bounds.
Число физических строк может вырасти на пересечения страниц. Лимиты запросов,
байтов, retry, сроков, catalog included IDs и шести календарей не меняются.

## Восстановление и приёмка

Это изменение кода само не разрешает merge, production, повторную доставку,
source HTTP, изменение OFF/пинов или reset бюджета. Упавший transfers run оставил
дневную reservation; её нельзя обнулить ради повторного запуска. Использовать
следующее естественное разрешённое окно и действующий общий лимит источника.
Не удалять старый batch и не выполнять массовую перепубликацию.

Перед новой доставкой нужен отдельный точный пакет: проверенный commit/CI,
новый target и rollback, host/mounted fingerprints, parser/identity compatibility,
условия OFF и штатного автомата, writer-free preflight, откат и postflight.
Уже одобренное окно прежнего выпуска не разрешает подменить его новым SHA.
Автоматический guard и его реакция на неуспешный transfers сохраняются.

Для первого штатного transfers сохраняют исходный полный report, raw bindings,
manifest/row identity, полный included roster и отчёт о бюджете/возрасте.
Поздний SUCCESS не переписывает исходный FAIL #1711. Для #1723 отдельно нужен
первый сезонный отчёт фактической новой версии; transfers его не заменяет.
Использовать существующий offline postflight из PR#1733 и существующий SLA reader.
У каждой приёмки сохраняют series/T0/UNKNOWN/holds. Code/data/interval impact
оценивают отдельно; эта оценка не является разрешением на journal `change`.
Полные сутки измеряют только после закрытия интервала и допустимой квалификации,
в пределах прежних sharedROOT/SQL лимитов. Close holds #1291/#1699 сохраняются.
